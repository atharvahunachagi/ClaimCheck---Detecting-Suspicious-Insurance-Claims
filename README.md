# ClaimCheck — AI-Powered Insurance Claim Fraud Detection

## 📌 Project Overview

**ClaimCheck** is a machine learning and deep learning project designed to identify potentially fraudulent insurance claims. It analyzes insurance policy and claim-related data to distinguish between legitimate and fraudulent claims.

The project compares traditional machine learning models with a neural network and uses Explainable AI (XAI) to identify factors that may contribute to a fraud prediction. It also generates an AI-style investigation summary to support manual claim review.

## 🎯 Objectives

- Detect potentially fraudulent insurance claims using historical data.
- Perform data validation, preprocessing, and feature engineering.
- Train and compare multiple classification models.
- Address class imbalance using class-weighting techniques.
- Tune XGBoost hyperparameters to improve model performance.
- Explain model predictions using SHAP.
- Generate an investigation summary highlighting suspicious claim characteristics.

## 📊 Dataset Description

The notebook uses `fraud_oracle.csv` as its input dataset.

The target column is:

- **`FraudFound_P`** — indicates whether a claim is classified as fraudulent or legitimate.

The notebook checks the dataset dimensions, class distribution, missing values, and sample records before preprocessing.

It also removes the `PolicyNumber` column when present because it is a unique identifier rather than a useful predictive feature.

The dataset contains numerical and categorical features related to insurance claims and policies. The notebook uses a stratified train-test split to preserve the target-class distribution across both sets.

## ⚙️ Project Workflow

### 1. Data Validation

The notebook:
- Loads the CSV dataset.
- Checks the number of records and columns.
- Examines the number of legitimate and fraudulent claims.
- Calculates the percentage of fraudulent claims.
- Checks for missing values.
- Displays an initial sample of the data.

### 2. Feature Engineering

Two additional features are created:

- **`VehiclePrice_to_Age`** — converts vehicle-age categories into numerical values.
- **`Price_Ratio`** — divides the encoded vehicle-price category by the encoded vehicle-age value.

These features are intended to provide additional information that the models can use to identify potentially unusual claim patterns.

### 3. Data Preprocessing

The notebook separates the predictors (`X`) from the target (`y`) and identifies numerical and categorical columns.

- **StandardScaler:** Standardizes numerical features.
- **OneHotEncoder:** Converts categorical features into numerical representations.
- **ColumnTransformer:** Applies the appropriate transformation to each feature type.

The dataset is split into training and testing sets using an 80:20 ratio, with `random_state=42` and stratification.

### 4. Machine Learning Models

**Random Forest Classifier**

A baseline ensemble model that combines predictions from multiple decision trees. The notebook uses `class_weight='balanced'` to account for the imbalance between legitimate and fraudulent claims.

**XGBoost Classifier**

A gradient-boosting model that builds trees sequentially to improve predictive performance. The notebook uses `scale_pos_weight=16` to give greater weight to fraudulent claims.

**XGBoost Hyperparameter Tuning**

GridSearchCV evaluates different combinations of:
- Number of estimators: 100 and 200
- Maximum tree depth: 3, 5, and 7
- Learning rate: 0.01 and 0.1
- Positive-class weight: 16

Three-fold cross-validation and ROC-AUC scoring are used to select the best configuration.

### 5. Deep Learning Using MLP

The notebook implements a Multilayer Perceptron using PyTorch.

The network consists of:
- Input layer based on the number of preprocessed features.
- Fully connected hidden layers with 256, 128, and 64 neurons.
- ReLU activation functions.
- Batch normalization and dropout in selected layers.
- A single output neuron for binary classification.

The training configuration includes:
- Adam optimizer
- Learning rate of 0.0005
- Batch size of 32
- 20 training epochs
- Binary cross-entropy with logits loss
- Positive-class weighting to address class imbalance

The sigmoid function converts the output logits into probabilities, and a threshold of 0.5 is used to produce class predictions.

### 6. Model Evaluation

The notebook evaluates model performance using:

- **ROC-AUC:** Measures how well the model distinguishes between the two classes across different thresholds.
- **Precision:** Measures the proportion of predicted fraudulent claims that are actually fraudulent.
- **Recall:** Measures the proportion of actual fraudulent claims detected by the model.
- **F1-score:** Combines precision and recall into a single metric.
- **Classification report:** Summarizes precision, recall, F1-score, and support for each class.

The notebook prints evaluation results for Random Forest, baseline XGBoost, tuned XGBoost, and the MLP model.

### 7. Explainable AI Using SHAP

SHAP (SHapley Additive exPlanations) is used to investigate the MLP's predictions.

The notebook:
1. Selects a background sample from the training data.
2. Creates a SHAP DeepExplainer for the trained PyTorch model.
3. Calculates SHAP values for a test sample.
4. Identifies three features with the largest positive SHAP contributions.
5. Prints an investigation summary containing the selected feature names and their impact scores.

This helps make the model's output more interpretable instead of treating the prediction as a black box.

### 8. Investigation Summary Generation

The notebook generates a text-based investigation summary that highlights selected features associated with a fraud prediction and recommends manual review.

This is a template-based narrative generated using Python string formatting. It is not a separate generative AI model.

### 9. Model and Data Export

The notebook saves the following artifacts:

- `fraud_mlp.pt` — trained MLP weights.
- `preprocessor.pkl` — fitted preprocessing pipeline.
- `cleaned_fraud_data.csv` — exported dataset containing the engineered features.

The notebook also includes code to copy these files into the designated Google Drive project folder.

- Suspicious claims should undergo human review before any final decision.
